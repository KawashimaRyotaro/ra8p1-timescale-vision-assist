# 開発順序

この順序は固定仕様ではありません。評価結果に応じて変更します。

## カメラ表示の評価結果

Renesas公式例を利用して、次の基本経路を実機で確認しました。

```text
OV5640 → MIPI CSI-2 → VIN → 外部SDRAM → GLCDC → LCD
```

この結果は経路全体の動作確認です。外部SDRAM、各画像バッファ、処理時間、
画像欠落、表示遅延は個別に測定できていません。

## 次の評価順序

一度に追加する要因を限定します。

1. 固定入力NPUベンチマークをEK-RA8P1で実行する
2. 推論出力の一致と、100回の推論時間分布を記録する
3. 同じモデルのCPU実行版を生成し、NPU版と比較する
4. カメラ画像から推論入力を作る前処理だけを評価する
5. カメラ、前処理、NPU推論を接続し、区間ごとの遅延を測る
6. μT-Kernelタスクへ処理を分離し、優先順位の影響を測る

カメラのカラーバーが正常で、ライブ映像の黄色みも軽減したため、AWB、AEC、AGCの
微調整は一旦保留します。AWBは自動白色調整、AECは自動露光調整、AGCは自動利得調整です。

## 統合システムの候補順序

1. リアルタイム処理の基盤
2. カメラ入力
3. 時間変化の解析
4. AI（Artificial Intelligence：人工知能）推論
5. 緊急処理と詳細処理の優先順位評価
6. 出力機能
7. 測定結果に基づく最適化

## 完了条件

各評価は次を記録して終了します。

- 何を確認したか
- 成功したこと
- 失敗したこと
- 測定値
- 学んだこと
- 最終設計へ反映するか

独立評価プロジェクトは途中で動かない状態を許容します。ただし、
`firmware/ra8p1/`と`main`ブランチの既知動作状態は保護します。
